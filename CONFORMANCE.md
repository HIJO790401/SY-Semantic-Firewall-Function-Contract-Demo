# Conformance and responsibility

Copying, citing, forking, passing a screenshot around, or using the author's name does not establish conformance or certification.

A scoped conformance claim must identify:
1. Exact source/version/hash, model digest and inference configuration.
2. The accountable principal and independently authorized function/task/argument boundary. Model output is never its own authority.
3. Prior permit returned before execution, binding task/function/arguments/rule version/scope, consumed once.
4. Actual allowlisted function execution and resulting value, not model-generated arithmetic presented as execution.
5. Fixed acceptance criteria, failures, missing-definition return and explicit terminal state. Invalid/STOP cases are not successful deliveries.
6. No extra execution or model calls after terminal replay; sufficient model completion prevents needless escalation.
7. Per-command raw input/output usage, rate source/date/currency/unit, reference-price calculation and actual-payment distinction.
8. The additional verified value, if a more expensive path is claimed to be better.

Missing evidence means NOT VERIFIED, not automatic author endorsement. A failing or modified implementation must label its version and divergence. Operators remain responsible for their own operation and representations, subject to applicable law. These requirements do not prevent truthful criticism or independent falsification.

The original 12 tasks test finite integer add/subtract and explicit refusal/return cases. They do not establish a universal agent, private-core validation, arbitrary tool safety or equivalence across all model tasks. A user can also define and close a task through natural language; this benchmark's direct-answer arm does not test the full iterative human-defined process.
